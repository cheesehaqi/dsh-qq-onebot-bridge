STT 试转写 （录一段或选音频文件 → 本地识别转 16kHz WAV / 云端原样上传 → 识别）

录音只在内存里转一圈：转写完成后就丢弃，不保存、不发 QQ。识别走宿主里的本地 SenseVoice（或云端 provider）。
为什么是 16kHz：宿主里的本地识别服务只接受 16kHz 单声道 16 位 WAV（平台会校验，别的采样率直接拒）， 16k 也是 SenseVoice 这类识别模型的训练采样率——更高的采样率（44.1/48k）在识别前也会被降采样，不会更准。 走云端 provider 时不转码（原样上传，采样率由云端决定）。TTS 试听那条链路也不受这个限制： 音频按服务商原样返回（本地 GPT-SoVITS 常见 32/44.1kHz），上面的格式会标出实际采样率。

为什么这样测 （出问题时先看这几条）

1. 状态里写着"宿主 speechToText：不可用"时，STT 走 dsh 一定失败 —— 先在 profile 里启用实验性的「语音输入」bundle 并重启宿主；
2. 宿主刚更新过插件时，/qqai/voice/* 是插件新注册的路由，要重启一次宿主才会挂上；
3. 控制台会自己找宿主：先看 qq-host-out.log 里带 token 的地址，找不到就从监听端口里认出 DSH 宿主 （桌面端自己起的宿主端口随机也能认）；两条都失败时状态里会写清楚卡在哪；
4. 转码要 ffmpeg 在 PATH（或插件里的 ffmpegPath 指对），失败原因会原样显示；
5. 这里不发 QQ、不改配置：真正的语音回复行为要看桥的「语音回复」开关与 TTS 配置。
