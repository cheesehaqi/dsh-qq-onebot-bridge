# 调试 / 排障（trace · 回放 · 体检 · 注入）

> 从 README 搬出来（README 太长了）。这份是给**想深挖某条消息为什么没回**的人看的；只想让它跑起来，看 [README](../README.md) 就够。
> 下面提到的控制台都在 `control/`（默认 `127.0.0.1:8799`），面板里点「控制台（独立进程）」会自动拉起。

每条入站消息都有一个 **traceId**，每个决策点（**包括每一次"不回复/丢弃/降级"**）都会留下 `stage + ok + reason + 耗时`。这是本版本的核心设计理念：出问题时不用猜。

| 想看什么 | 在哪看 |
|---|---|
| **6 条硬约束此刻达标吗** | 控制台最上面「**硬约束验收台**」：6 行状态灯 + 机器上现有的证据 + 该点哪里的提示，每 30 秒自动重算 |
| 单条消息的完整决策链 | 控制台「实时事件流」点任意一行 → 「决策链」显示时间轴、停在哪一步、为什么 |
| 为什么机器人不回复 | 「实时事件流」筛"仅被拒/失败"，最常见原因直接列出（如 `mention: 群聊未 @ 机器人`） |
| 每个端口的占用与在线 | 控制台「端口 / 进程」（6700 的连接数即机器人在线） |
| 一键排查 | 控制台「一键体检」：15-19 项 pass/fail + 修复建议（依赖路径、端口、链路、快照、错误、闸门拒绝…） |
| 想发给别人 / 留一份 | 控制台右上角「体检报告」→ `/report`：一整页可打印成 PDF、可一键复制，结论 + 先修 + 明细 + 6 条约束都在里面 |
| 生效配置（为什么功能没生效） | 控制台「运行快照」里的"关闭中的开关"；完整字段在 `qq-runtime.json` 的 `features`（不含任何密钥） |
| 打包给别人看 | 「导出诊断包」→ 一个 zip（事件流/审计/桥日志/宿主日志/运行快照/体检报告/环境信息） |
| 文件级排查 | `qq-trace.jsonl`（结构化事件，可 `jq`/grep）、`qq-bridge-debug.log`、`qq-actions.log`（写操作审计）、`qq-host-out.log`/`err.log` |

相关配置：`traceEnabled`（默认开）、`traceLevel`（`debug` 全量 / `warn` 只留问题）、`traceMemorySize`、`traceFile`。
调试接口（控制台，token + Origin 双重校验）：`/api/trace`、`/api/stream`（SSE）、`/api/runtime`、`/api/diagnose`、`/api/export`。

### 录制 · 离线回放 · 事件注入（v0.4 阶段 3）

前两项解决了"现在发生了什么"，这三项解决"这条消息当时为什么这样、换成别的输入会怎样"。

| 能力 | 怎么用 | 说明 |
|---|---|---|
| 录制 | 自动 | 桥收到的每条消息/通知/请求都追加到 `qq-inbox.jsonl`（可 JSON 逐行解析、按大小轮转），只写本机、不改任何回复行为 |
| 离线回放 | 控制台「录制 · 回放 · 注入」→ 某行「回放这条」／「回放最近 5 条」 | 在**沙箱目录**里用**真实桥代码**重跑这条消息：dry-run 拦截所有出站、不建任何 QQ 连接、源目录一个字节都不改。结论逐条给出"会回复/静默/出错 + 原因 + 会发送什么" |
| 事件注入 | 控制台填 群号/QQ 号/文本 → 「注入」 | 写一行到 `qq-inject.jsonl`，桥按 `injectIntervalMs`（默认 2s）轮询后**走真实管线**处理；`injectDryRun`（默认开）下所有出站调用被拦截并计数，注入内容永远不会真的发到 QQ |

回放的保真度来自**运行时快照里的线上决策配置**（白名单、安静时段、各功能开关等 28 项，见 `qq-runtime.json` 的 `replay`）：否则插件默认值里"白名单为空 = 拒绝一切"会让回放全部判成静默。回放里**不含真实模型输出**——模型那一轮用一条带 `[回放]` 前缀的模拟回复代替，用来验证链路与分支，不验证措辞。

排障要点：

- 注入通道未开启时会**直接报错并说明开关名**（`injectEnabled`），不会静默丢进队列；
- 注入触发的 **agent 回合是异步的**：dry-run 窗口只在同步阶段开着，所以模型真正的回复会在事件流里被单独拦下（`注入回合的模型回复已被拦截（dry-run，未发送）：<原文>`）——注入既能走真实管线，又不会漏发一条；真人消息不受影响（收到真实消息立即解除该标记）；
- 回放的帧在事件流里标为 `replay: 离线回放（沙箱 + dry-run，不碰 QQ）`，注入的帧标为 `inject: 来自注入器`，两者不会互相误判；
- 桥启动时若队列里已有历史行，会跳过它们并在事件流里记一条"本次启动跳过 N 行（只处理启动后新增的行）"，避免重启后重放旧注入；
- 注入的帧不会被二次录制（否则回放/注入会互相激发）；
- 回放沙箱默认保留最近 5 次，更旧的**移入回收站**（`qq-replay/_trash/<日期>/`），不做物理删除。

相关配置：`recordInbound`（默认开）、`inboxFile`、`inboxRedact`、`injectEnabled`（默认关）、`injectFile`、`injectDryRun`（默认开）、`injectIntervalMs`。
调试接口：`/api/inbox`、`/api/replay`、`/api/inject`、`/api/queue/clear`。

### 硬约束验收台（v0.4 阶段 4）

上面两条解决了"现在发生了什么"和"当时为什么这样"。验收台解决第三个问题：**设计理念有没有真的落地**。

`GET /api/acceptance` 把 6 条硬约束逐条用**机器上现有的产物**算成 `✅ 达标 / ⚠️ 有提示 / ❌ 不达标 / ❔ 证据不足`，并给出证据与下一步：

| 约束 | 判定用的证据 |
|---|---|
| ① 无静默分支 | 最近 500 条事件里所有 `ok:false`（被拒/失败）事件是否都带非空 reason；缺的会点名 stage |
| ② 可关联（traceId） | 消息级事件的 traceId 覆盖率、有多少条消息真正走完 `inbound→reply` |
| ③ 可回放 | 录制条数 + 最近一次回放的统计与**安全保证**（dry-run 开、QQ 连接 0、cwd 已沙箱化）；dry-run 被关掉直接判不达标 |
| ④ 可体检 | 体检通过数/失败数/blocker 数与结论，失败项点名 |
| ⑤ 可导出 | 诊断包会收集的产物有几类在位（或最近一次导出的体积与文件名） |
| ⑥ 可注入 | 通道开关、dry-run 开关（关掉→不达标，因为会真发 QQ）、已消费行数、以及**拦下过几次异步 agent 回合的回复** |

每一项都能点「去看 →」跳到对应卡片（事件流/决策链/回放结果/体检/日志/注入）；结论为 `all-green / partial / unknown / broken` 四种。
纯函数实现（`control/lib/acceptance.mjs`），所以每条分支都有断言覆盖；面板每 30 秒自动刷新，回放结束后立刻重算。

### 一键体检报告（独立页 `/report`）

验收台是给**自己**看的：18 项检查与 6 条约束平铺在几张卡里，想发给别人、留一份存档或贴进 issue 都只能截图。
`/report` 把两组既有产物（逐项体检 + 6 条硬约束）合成一份报告：

- 顶部一句话结论（`阻断 / 告警 / 证据不足 / 全绿`）＋ 关键计数（体检通过数、阻断项、约束达标数…）；
- **先修这些**：按后果排序 —— 阻断的体检项 → 不达标的硬约束 → 告警项，每项带一句怎么修，最多 6 条；
- **六条硬约束**：逐条证据与 `去看 →`（跳回控制台对应卡片并高亮，地址带 `?focus=`）；
- **体检明细**：按 本机依赖 / 端口·进程 / 链路 / 运行快照 / 事件面 / 审计与文件 分组，失败项排在组首；
- **关键事实**：桥版本、已运行时长、会话数、被闸门拒绝次数、事件总数、快照年龄。

页面**只读**（不发任何 POST）、零外部依赖、`@media print` 下白底黑字（`Ctrl+P` → 另存为 PDF）；
「复制报告」拿的是服务端 `formatHealthReport()` 的文本，可以整段贴进 issue。判定与文案都在
`control/lib/report.mjs`（纯函数），`test/report-unit.mjs` 钉住结论优先级、分组与页面接线。

接口：`GET /api/report[?fresh=1]`（token + Origin 与其它接口相同；`fresh=1` 绕过体检的 5 秒缓存，
页面上的「重新体检」用的就是它）。

### 设置项变更历史（控制台卡片）

「改完就忘」比「改错」更难查：路径配置、WebUI 端口、WS 客户端地址散在三个文件里，改动只在当时那一下有反馈。
控制台的「设置项变更历史」卡把**设置文件的 old → new** 留下来：

- 记录范围：`qq-control.json`（控制台的路径/端口配置）、NapCat 的 `webui.json` 与 `onebot11_<uin>.json`；
- 触发方式：服务端只在**写设置的接口**（`POST /api/config`、`/api/accounts/config`、`/api/accounts/network*`）
  前后各拍一次快照再机械 diff；启动/停止/回放/注入这类"操作"不记（那是事件流与 `qq-actions.log` 的事）；
- 存储：`<控制台启动时的工作目录>/qq-settings-history.jsonl`，一行一条；超过 256 KB 自动只留尾部 64 KB；
- 脱敏：`token / secret / password / apiKey` 这类键**永不落盘**，值变化只记 `token：*** → ***`（并标「值已隐藏」）；
- 读取：`GET /api/history?limit=200&q=关键词`（token + Origin 同其它接口）；页面按关键词即时过滤，
  「复制文本」给整段（不受过滤影响）；
- 只读：不提供"还原"。要回滚请用账号中心的配置备份（写前会先复制 `.bak`），这条边界是故意的。

规则只有一句：**快照盯文件、不盯接口参数**。接口会加会改，文件不会 —— 只要写到了上面那几份文件，历史就记得到。

### 语音调试（独立页 `/voice`）

老功能回访：语音模块（`lib/stt.js` / `lib/tts.js`）以前只能"给机器人发一条语音"来间接验证，出错时面板上只有
"没转写 / 没声音"。控制台的「语音调试」是**单独一页**（`/voice`，左侧导航入口）——语音要反复换音色/语言试听、
录一段看转写，放在总览里会被 30 秒自动刷新冲掉。

| 想确认什么 | 怎么试 | 说明 |
|---|---|---|
| 语音模块卡在哪 | 页面顶部状态 | 开关关着 / 本地 TTS 缺参考音频 / 云端缺 key / 宿主没有 `speechToText` —— 每个卡点都带"去哪儿开" |
| TTS 能不能出声、音色对不对 | 输入一句话 →「合成并试听」 | 音频只在页面里播放，**不发 QQ**；显示 provider / 字节数 / 耗时 |
| STT 能不能转写、准不准 | 「开始录音」说一句，或「选音频文件」 | 浏览器录音（webm/ogg）或任意音频文件 → 宿主 ffmpeg 转 16kHz 单声道 WAV → 本地 SenseVoice（或云端）；显示转写文本、耗时、转码后大小 |

**细调**（全部是**这一次试听的覆盖**，不写回配置；页面按 provider 只显示用得上的字段）：

| provider | 可调 |
|---|---|
| Azure | 音色、风格（`mstts:express-as`）、语速 %（-50…100）、音调 st（-12…12）、音量 %（-50…50） |
| OpenAI 兼容 | 音色、语速倍率 `speed`（0.25…4） |
| GPT-SoVITS | 参考音频路径、参考文本、参考语言、语速 `speed_factor`（0.5…2）、`temperature`（0.01…2）、`top_k`（1…100）、`top_p`（0…1）、`repetition_penalty`（0.5…2）、`seed`（-1 = 随机） |
| STT | 识别语言（auto / 中文 / 英文 / 日文）、云端模型 id |

**音调**：Azure 走原生 SSML `prosody pitch`；本地 GPT-SoVITS / OpenAI 走**内置变调**（重采样 + WSOLA，
只变调、时长基本不变，±12 半音）——本地 wav 不需要 ffmpeg，云端 mp3 只用 ffmpeg 做一次解码（精简版 ffmpeg 也够）。
语言界面只保留**自动 / 中 / 英 / 日**（默认自动；GPT-SoVITS 的 `text_lang=auto` 在 v1/v2 的语言表里都有，中英日混说也稳）。

越界参数会**直接报错并点名范围**（不悄悄夹紧——"设了 3 倍速实际 2 倍"比报错更难查）；没填的字段一律不发送，
老版本 GPT-SoVITS 也不会被多余字段打挂。试听记录保留最近 5 条（各带播放器与参数摘要）方便 A/B。
要长期生效请去 DSH 设置页改。

链路：控制台页面 → `POST /api/voice/tts|stt`（token + Origin）→ supervisor 找宿主（① `qq-host-out.log` 里带 token 的地址；
② 找不到就从本机监听端口里认出 DSH 宿主，桌面端自己起的宿主端口每次可能不同，插件路由不要 token）→
宿主 `POST /qqai/voice/{tts,stt}`（同源 + JSON + 体积门禁）→ `lib/voice.js` → `lib/tts.js` / `lib/stt.js`。

排障要点：

- **状态显示"找不到宿主"**：日志里没有带 token 的地址（控制台没启动过宿主），也没从监听端口认出 DSH 宿主
  —— 先启动（或重启）一次宿主；状态里会写出实际找到的宿主地址；
- **状态显示"宿主在 …，但没有 /qqai/voice 接口（插件还是更新前的版本）"**：宿主在跑，但加载的是旧插件代码。
  插件热重载会复用 ESM 模块缓存，不会重新求值，所以**必须重启一次宿主**（桌面端就是重启 DSH）；
- 录音用浏览器 `MediaRecorder`，需要麦克风权限；不给权限就用「选音频文件」；
- ffmpeg 在 PATH 里（或 `ffmpegPath` 指对）才能转码 —— 这也是桥转写语音的前置条件，调试卡会把失败原因写出来；
- **为什么是 16kHz**：宿主里的本地识别服务（`speechToText`）**只接受** 16kHz 单声道 16 位 WAV（平台会校验，
  其它采样率直接抛 Invalid speech WAV）；16k 也是 SenseVoice 这类模型的训练采样率，44.1/48k 在识别前一样会被降采样，
  不会更准。**TTS 链路不受此限制**：试听拿到的是服务商原样的音频（本地 GPT-SoVITS 常见 32/44.1kHz，
  Azure 24kHz mp3），页面上会把 WAV 的实际采样率标出来；桥发 QQ 时本地 wav 会转 mp3（`ttsLocalConvertToMp3`），
  转码不会降采样率；
- 卡片只做"本机试一下"：**不经过 QQ 发送链路**，也不会改任何配置。
